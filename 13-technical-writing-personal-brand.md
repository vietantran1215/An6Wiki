# Technical Writing & Personal Brand

## 1. Objective

Technical writing converts experience into durable, inspectable knowledge. The priority is technical credibility rather than content volume.

## 2. Editorial pillars

- Architecture;
- AI Engineering;
- Production Engineering;
- Engineering & Business.

Technologies are tags, not pillars.

## 3. Article structure

1. Problem.
2. Why it matters.
3. Mental model.
4. Architecture/flow.
5. Implementation.
6. Failure modes.
7. Security/reliability.
8. Trade-offs.
9. Decision rules.
10. References.

## 4. Case-study structure

```text
Problem
 → Constraints
 → Requirements
 → Architecture
 → Decisions
 → Trade-offs
 → Implementation
 → Observability
 → Security
 → Results
 → Lessons
```

## 5. Clear-writing patterns

Constant Topic, Old → New, Whole → Parts, and Preview → Sequence.

## 6. Editorial pipeline

```text
Idea
 → Research
 → Draft
 → Technical review
 → English/style review
 → Claim verification
 → Citation pass
 → Diagram/visual review
 → Metadata
 → Final read
 → Publish
```

## 7. Quality contract

Define the reader problem, key claim, evidence, counterargument, production relevance, and the decision the reader can make afterward.
