# Technical Writing & Engineering Evidence

## Objective

Technical writing should convert experience into reusable reasoning.

## Strong article structure

```text
Problem
 → constraints
 → mental model
 → architecture
 → implementation
 → failure modes
 → trade-offs
 → decision rules
 → references/evidence
```

## Claims

Classify claims:

- factual;
- measured;
- experiential;
- opinion/decision.

Measured claims need methodology.

## Example benchmark disclosure

```text
Corpus: 5,000 internal-policy chunks
Queries: 200 labeled questions
Metric: Recall@10
Dense-only: 0.81
Hybrid + RRF: 0.89
Reranked: 0.93
```

Without corpus/query detail, the numbers are difficult to interpret.

## Case studies

A credible case study explains:

- initial problem;
- failed attempts;
- constraints;
- decision;
- production incident if relevant;
- result;
- limitations.

## Rule

The strongest personal technical brand is accumulated engineering evidence, not adjectives such as "expert" or "innovative."
