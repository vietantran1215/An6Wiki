# Capstone & Evidence-Based Learning

## Evidence chain

```text
Business problem
 → requirement
 → architecture
 → task/user story
 → code
 → test
 → deployment
 → observation
 → technical defense
```

## Weekly artifacts

A strong engineering program can require:

- Architecture Spec;
- Test Spec;
- code/PR;
- demo;
- retrospective.

No artifact means no evidence.

## Progressive capstone

Each phase should:

- run independently;
- have no hidden gap from prior phase;
- introduce a small number of new concepts;
- preserve previous behavior;
- add tests;
- update architecture.

## Reproducibility

A learner should be able to clone and run with minimal setup.

Provide:

- non-Docker path where reasonable;
- Docker path;
- seeded data;
- test script;
- expected output.

## Technical defense

Ask the learner to explain:

- why this design;
- alternatives;
- failure modes;
- security;
- observability;
- rollback.

## Rule

A capstone should prove engineering judgment, not merely demonstrate that a UI works.
