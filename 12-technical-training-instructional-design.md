# Technical Training & Instructional Design

## 1. Objective

The goal is not content exposure. The goal is observable capability.

## 2. Preferred teaching flow

```text
Pain point / business problem
 → concept
 → big picture
 → components
 → mechanics
 → concrete example
 → code/lab
 → result
 → trade-offs
 → knowledge check
```

For difficult topics, show the diagram before the command.

## 3. Learning-unit structure

1. Competency.
2. Learning objectives.
3. Theory.
4. Reference walkthrough.
5. Guided lab.
6. Experiments.
7. Assessment.
8. Mastery criteria.
9. External learning links.

## 4. Rules

Explain prerequisites, prefer concrete examples before abstractions, use explicit transitions, avoid hidden lab dependencies, make labs reproducible, and explain why instead of only listing commands.

## 5. Capstone traceability

```text
Business goal
 → Requirement
 → Architecture
 → User story / acceptance criteria
 → Issue
 → Code
 → Test
 → Deployment
 → Demo / technical defense
```

## 6. Artifact-based assessment

High-value outputs include Test Specification, Architecture Specification, code/PR evidence, evaluation report, demo, and technical Q&A.

## 7. Self-review

Are prerequisites explicit? Is the sequence manageable? Is the lab reproducible? Are examples correct? Does the learner produce evidence? Are evaluation criteria objective?
